# F03.1: Correct Domain State and Plan Contracts

## Scope

Close the F03 review findings without introducing Room, Android storage APIs,
WorkManager, production adapters, or real file I/O.

## Delivered

- Corrected the Draft and ImportRecord transition contracts.
- Added `WAITING_FOR_USER_AUTH` and its resumable Plan transitions.
- Split static API permission capability from runtime `ScanCoverage`.
- Restricted sweep and whole-batch organization to completed FULL scans.
- Added typed payloads for all five Plan types.
- Added type-specific required steps and payload validation, including the
  300-item source-cleanup authorization chunk limit.
- Replaced context-free storage error mapping with operation-aware failure
  resolution and explicit domain failures.
- Added workspace Trash move and restore Port signatures without adapters.
- Replaced sample transition tests with complete enum transition matrices.

## Acceptance

- [x] All Plan types carry typed, validated payloads.
- [x] Draft, Plan, Album, ImportRecord, and Trash transitions are exhaustively
  checked against their allowed matrices.
- [x] FULL/PARTIAL/UNKNOWN coverage and scan completion gate destructive batch
  behavior independently from Android API level.
- [x] Provider unavailability remains retryable instead of being mislabeled as
  Manifest recovery.
- [x] No real storage behavior or platform dependency was introduced.
- [x] Domain tests, architecture guards, app-policy guards, and baseline
  verification pass locally.

## Deferred

- Release policy, Wrapper, EOL, CI, and launcher-icon hardening remain F02.2.
