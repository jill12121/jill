## S03.1 Contract

The dependency-free `:spikes:s03-ocr` Kotlin/JVM module classifies one
measured OCR run against an explicit budget:

- `PASS` requires a complete, sufficiently sampled run using a bundled model,
  no declared Internet permission, and precision, recall, failure count, and
  P95 latency inside every budget.
- `FAIL` is fail-closed for remote or unknown model delivery and any declared
  Internet permission, even when the run is incomplete. Complete quality
  failures report every exceeded budget in stable order.
- `PENDING` represents incomplete or undersampled valid evidence, including an
  empty pre-run snapshot.
- `INVALID` represents impossible counts or negative durations.

Precision and recall use integer permille arithmetic so exported evidence does
not vary with floating-point formatting. Budget values are classifier inputs;
S03.1 does not freeze production thresholds.

Six unit tests cover passing evidence, offline fail-closed behavior, pending
evidence, deterministic multi-budget failure, zero-recognition failure, and
invalid metrics. Architecture guards keep the module free of Android and
project dependencies and prevent production modules from depending on spikes.

## S03.2a Measurement Core

- Token matching applies Unicode NFKC normalization, `Locale.ROOT` lowercase,
  and Unicode letter/number tokenization.
- Matching uses multiset intersection, so duplicate expected words cannot be
  satisfied by one recognized occurrence.
- Inputs are bounded to 4,096 tokens per sample. The recorder retains only
  aggregate counts and durations, never expected or recognized text.
- Recognition failures count as samples with all expected tokens missed.
- Synchronized recording and checked integer aggregation prevent concurrent
  sample loss and silent count wraparound.
- P95 uses nearest rank over nanoseconds and rounds up to whole milliseconds.
  Empty snapshots remain valid and incomplete; completion rejects late writes.

Seven additional tests cover normalization, multiplicity, invalid fixtures,
P95, aggregate snapshots, late writes, negative durations, and 8-thread
recording. The S03 module now has 13 tests.

## S03.2b Android Harness

- `:spikes:s03-ocr-harness` is a separate application with application ID
  `com.galleryorganizer.spikes.s03.harness`. No production module depends on
  it, and it depends only on the S03 contract plus bundled ML Kit Latin text
  recognition `16.0.1`.
- The app generates 100 deterministic `pixel-5x7-v1` PNG fixtures under its
  own `filesDir`, records corpus count, bytes, and SHA-256, and processes them
  sequentially with `InputImage.fromBitmap`.
- The final APK removes transitive `INTERNET`, `ACCESS_NETWORK_STATE`, and
  AndroidX dynamic-receiver permissions. Runtime evidence independently reads
  the installed package permissions so an Internet regression fails closed.
- Result schema 2 contains device, Android release, security patch, GMS Core,
  and corpus provenance plus aggregate token,
  failure, latency, decision, and violation fields. Expected and recognized
  OCR text are never written to JSON, logs, or status UI.
- Three Robolectric tests cover the merged permission set, deterministic
  app-private corpus generation, and
  aggregate-only export. Together with the contract/core tests, all 16 S03
  tests pass.

## S03.2c Evidence Guard

- Harness `0.1.1` records whether `com.google.android.gms` is installed, using
  package visibility only and adding no permission. This makes the no-GMS
  device requirement machine-verifiable.
- `scripts/verify-s03-evidence.ps1` accepts only schema-2 field names, checks
  device/corpus provenance, recomputes aggregate rates and classifier output,
  rejects raw OCR/fingerprint fragments, and requires distinct `middle-tier`
  and `no-gms` physical devices with opposite GMS states.
- `scripts/test-s03-evidence.ps1` covers pending, malformed, online, remote
  model, role mismatch, raw-data leakage, duplicate-device, FAIL, and GO
  paths. CI runs the negative guard.
- With no measured rows, the guard reports `PENDING (0/2)` rather than GO.
