## S05.1 Contract

The benchmark receives an explicit budget and measured metrics. It reports:

- `PASS` only for a complete, sufficiently sampled run within every budget.
- `FAIL` for OOM, fetch failures, heap excess, frame P95 excess, or fetch P95
  excess.
- `PENDING` for incomplete or insufficiently sampled runs.
- `INVALID` for impossible metric values.

OOM is fail-closed even when the run terminates before minimum sample counts.
Violation ordering is stable so exported evidence and tests remain comparable.
Budget values are inputs to the classifier; S05.1 does not claim that the
initial values are final production limits.

When a valid run fails, tuning reductions are attempted in this fixed order:

1. reduce prefetch distance;
2. reduce memory-cache capacity to its configured floor;
3. reduce thumbnail cell edge to its configured floor.

## S05.2b Harness

The harness application ID is `com.galleryorganizer.spikes.s05.harness`. It
requests no permissions and depends only on `:spikes:s05-thumbnail`. Each run
creates 96 controlled PNGs under `filesDir/s05-thumbnail-fixtures`, records
frame/fetch/failure/heap/OOM metrics during a ten-second scroll, and writes
`filesDir/s05-results/latest.json`.

## S05.2c Evidence Review

Exported harness results are reviewed before any budget freeze. The result JSON
uses schema 2 and adds device provenance: manufacturer, model, API level,
Android release, security patch level, and a SHA-256 hash of the build
fingerprint. The raw `Build.FINGERPRINT` never leaves the device, matching the
S01/S02/S04 evidence rule.

Evidence files are named after the required matrix rows and reviewed with
`scripts/verify-s05-evidence.ps1`:

- `docs/evidence/s05/android11.json`
- `docs/evidence/s05/target.json`
- `docs/evidence/s05/oem-a.json`
- `docs/evidence/s05/oem-b.json`

The verifier rejects unknown schema versions, raw fingerprint fragments,
forbidden identity fields, fixture drift, and PASS claims without the minimum
frame/fetch samples, without zero failed fetches, or with an observed OOM. It
also rejects two rows that hash to the same physical device. Missing rows report
PENDING; aggregate GO is printed only when all four rows are present, distinct,
and PASS. `scripts/test-s05-evidence.ps1` keeps those rules under negative test.
Tooling is committed as `290e4a5` and passed Remote Verify `40667099458`;
measured device rows remain PENDING.

The verification host has no `adb`, so harness version `0.1.3` adds a
`Copy result JSON` action that puts the compact result into the clipboard after
a run. Clipboard handoff is user-mediated, needs no permission, and keeps the
result inside app-private storage until the user pastes it.
