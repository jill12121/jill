## Probe
After independent review, run S01 first and open S04. The current-target S01
and S02 evidence is already complete and must not be rerun. S04 displays the
completed count and selects the next missing cutoff automatically. For each
cutoff:

1. Prepare the cutoff in a random marker-owned `.s04-probe-<token>` sandbox.
   Preparation persists `PREPARING` before mutation and `READY` only after the
   cutoff is complete.
2. Force-stop `com.galleryorganizer.spikes.suite`.
3. Reopen S04. Only after the process restart does
   `Observe after restart` become available; select it once.

Only a `READY` stage may be observed. A `PREPARING` stage is incomplete and is
cleaned without becoming evidence. Observation in the same process returns
`PROCESS_RESTART_REQUIRED` and performs no cleanup. After a new process starts,
S04 re-enumerates final/tmp/bak, counts parseable JSON candidates, chooses
final then tmp then bak, classifies provider overwrite behavior from exact
display names and parsed generations, and commits `OBSERVED` before cleanup.
If cleanup is interrupted, the next launch resumes it without repeating the
observation. Partial or incompatible pending records cannot be reset into a
new run. Missing persisted roots are recovered only from one exact owned
sandbox; ambiguous or failed queries require retry. Deletion is re-queried
before pending state is cleared.

Overwrite measurement first removes only marker-owned or legacy exact-owned
fixtures and confirms absence. Provider-renamed fixtures are recognized by
their content marker. Query, read, or delete uncertainty returns
`QUERY_RETRY_REQUIRED` without committing overwrite evidence.

PASS requires all four cutoff observations, a process restart for each, at
least one parseable candidate, a recovery choice, a closed overwrite outcome,
and successful cleanup. Every observation must share one run ID and tree URI
SHA-256 hash and carry valid schema/probe/app/device provenance. Mixed runs or
roots fail; the raw build fingerprint is never exported. Any pending stage
suppresses a stale PASS.

After all four cutoff observations complete, select `Copy PASS result JSON`
and return the copied payload. `Copy diagnostic JSON` is not final evidence.
Force-stop and relaunch are performed through the device UI; ADB and USB
debugging are not required.
