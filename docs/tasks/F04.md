# F04: Room, Fake Ports, and FaultPlan

## State

PLANNED. Implementation may start because F03.1 and F02.2 are committed and
remote Verify run `39365176154` passed on `master`.

## Goal

Provide deterministic, testable metadata persistence and in-memory storage
substitutes for later Scanner, Plan, Journal, and Recovery work without
enabling production external-storage behavior.

## Allowed

- Room entities, DAOs, database configuration, schema export, and migration
  tests for app-private metadata.
- In-memory implementations of `SourceReader`, `WorkspaceGateway`,
  `ManifestStore`, and `PermanentDeleter` in test-only source sets.
- Deterministic `FaultPlan` and virtual clock support without sleeps.
- JVM and Android local tests.
- Test-only Hilt bindings when a test needs composition-level verification.

Fake ports must not be bound from the release application graph.

## Forbidden

- MediaStore, SAF, `ContentResolver`, `DocumentsContract`, or `DocumentFile`.
- Real Download scanning or organizer-root creation.
- Real `.nomedia`, `.part`, Manifest, Journal, copy, rename, SHA read, restore,
  source cleanup, or external-file deletion behavior.
- System deletion authorization intents.
- WorkManager, foreground services, OCR, networking, accounts, or uploads.

S01 continues to block workspace and copy execution, S02 blocks scanning and
source cleanup, and S04 blocks disk Journal and recovery execution.

## Sequence

### F04.1: Fake Ports and FaultPlan

- Add test-only in-memory Fake implementations for all four storage ports.
- Trigger throw, partial-write simulation, and process-kill simulation by
  deterministic operation number.
- Record operations and expose inspectable state before and after each fault.
- Prove failures never fake unexecuted completion or source deletion.
- Prove recovery inputs remain constructible without creating disk files.

### F04.2: Room Schema and Constraints

Implement and conflict-test the frozen constraints:

- `FileFact UNIQUE(rootId, relativePath)`
- `AlbumMembership UNIQUE(albumId, imageId)`
- `AssetFile UNIQUE(imageId, fileId)`
- `Evidence UNIQUE(contentKey, type, analysisVersion, evidenceKey)`
- `UserState PRIMARY KEY(imageId)`
- `SourceDecision PRIMARY KEY(sourceKey)`
- `BatchMember UNIQUE(batchId, fileId)`
- `DraftAction UNIQUE(draftId, fileId)`
- `JournalStep UNIQUE(operationId, stepIndex)`
- `TrashEntry PRIMARY KEY(trashEntryId)`

Also add the specified indexes for `ImportRecord`, `Plan`, `Journal`, and
`TrashEntry`. An active Draft has a unique non-null `activeKey`; archival or
invalidation clears it so history cannot block a new active Draft.

### F04.3: Minimum Fake Integration

Cover fingerprint invalidation, import source/copy linkage, partial media
access, storage full, target conflicts, cleanup denial, interrupted copy,
pre-Manifest interruption, and in-memory Journal semantics.
