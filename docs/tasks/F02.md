# F02: Module Boundaries, DI, and Architecture Checks

## Scope

Establish the dependency direction, composition root, and automated boundary
checks required by F02. This task deliberately adds no persistence, storage
adapter, Android storage API, source cleanup, or real file I/O.

## Delivered

- Added `core:contract`, `domain`, `data`, and `presentation` Gradle modules.
- Made `data` depend on `domain` so future repository adapters can implement
  domain-owned interfaces without reversing the dependency direction.
- Defined the approved port names as method-free contracts in
  `core:contract`; behavior is deferred to the dependent approved features.
- Kept `app` as the sole composition root through `AppContainer`.
- Added a Konsist test to ensure domain production code has no Android,
  Compose, or Room imports.
- Added architecture guard scripts and CI coverage for:
  - required modules and permitted Gradle dependencies;
  - no direct port imports from presentation;
  - no Android/Compose/Room import from domain;
  - Scanner, Analyzer, and AlbumEditor never depending on
    `PermanentDeleter`;
  - no real filesystem, MediaStore, ContentResolver, or DocumentFile API.
- Verified normal operation and three fault paths: platform import in domain,
  filesystem reference in domain, and direct contract import in presentation.

## Acceptance

- [x] The dependency graph is `presentation -> domain <- data`; `domain` and
  the current data adapter bindings share `core:contract`.
- [x] `app` is the only composition root.
- [x] Domain has a Konsist architecture test.
- [x] Static guard rejects forbidden imports and real I/O.
- [x] No storage or business behavior is present.
- [x] CI runs the architecture fault-path test and `:domain:test`.
- [x] Android 12+ cloud backup and device transfer rules exclude the complete
  app root, in addition to `allowBackup=false`.

## Risk and Deviation

- No device gate is consumed and no runtime storage capability is enabled.
- Konsist is test-only and scoped to `domain`; the repository-wide PowerShell
  guard covers cross-module rules and the explicit F02 I/O freeze.
- Local Gradle tasks report `BUILD SUCCESSFUL`; the host sandbox separately
  denies Java/Kotlin telemetry files outside the repository and can force a
  non-zero command exit after task completion.
