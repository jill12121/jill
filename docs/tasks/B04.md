## B04.1 Delivered

- Manual scans require an explicit `userInitiated` request.
- Each session accepts 1 to 100 unique content keys.
- Immutable session state supports confirmation, running, pause/resume,
  completion, cancellation, and failure without allowing invalid transitions.
- Progress cannot exceed the request and completion requires every subject.
- Rule hits contain only content identity, rule identity, permille score, and
  analysis version. There is no recognized-text field.
- Evidence drafts use fixed masked detail and SHA-256 stable identity derived
  from the rule/type/masked detail contract.
- Four unit tests cover request bounds, transitions, progress, and private
  aggregate Evidence generation.

## Boundaries

No production OCR dependency, source-byte adapter, Room write, UI, automatic
trigger, background execution, or feature-flag enablement is included.
The missing no-GMS S03 row remains release-blocking.

## B04.2 Delivered

- `ManualOcrRecognizer` returns only bounded structured rule hits or failure;
  recognized text cannot cross the port.
- `ManualOcrRunner` processes subjects in stable request order, deduplicates
  Evidence by stable identity, and completes only after every subject.
- Recognizer failure stops before later subjects while preserving prior masked
  Evidence; cross-content results fail closed without recording progress.
- The deterministic Fake exists only in test source. Three orchestration tests
  cover completion, adapter failure, and invalid-result isolation.
