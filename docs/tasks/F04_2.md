# F04.2: Room Schema and Constraints

## State

COMPLETED locally. Remote Verify is pending.

## Scope

F04.2 adds only app-private Room metadata:

- 15 Room entities from the v0.3.1 architecture model;
- one metadata DAO with fail-closed inserts;
- a version 1 Room database with schema export;
- deterministic local tests for uniqueness, indexes, Draft lifecycle cleanup,
  and the migration baseline.

No production database binding or repository is added.

## Frozen Constraints

The schema enforces:

- `FileFact UNIQUE(rootId, relativePath)`;
- `AlbumMembership UNIQUE(albumId, imageId)`;
- `AssetFile UNIQUE(imageId, fileId)`;
- `Evidence UNIQUE(contentKey, type, analysisVersion, evidenceKey)`;
- `UserState PRIMARY KEY(imageId)`;
- `SourceDecision PRIMARY KEY(sourceKey)`;
- `BatchMember UNIQUE(batchId, fileId)`;
- `DraftAction UNIQUE(draftId, fileId)`;
- `JournalStep UNIQUE(operationId, stepIndex)`;
- `TrashEntry PRIMARY KEY(trashEntryId)`;
- `Draft UNIQUE(activeKey)` for non-null active keys.

The DAO clears `activeKey` atomically when an editing Draft becomes stale and
when a stale Draft is archived. SQLite permits multiple null active keys, so
historical Drafts cannot block a new active Draft for the same scope.

The specified lookup indexes are present for:

- `ImportRecord(sourceFileId)`;
- `ImportRecord(targetFileId)`;
- `Plan(draftId, type)`;
- `Journal(planId)`;
- `TrashEntry(fileId)`.

## Schema and Migration Baseline

Room schema export is configured at:

`data/schemas/com.galleryorganizer.data.room.OrganizerMetadataDatabase/1.json`

`MigrationTestHelper` creates and validates version 1 from that committed
schema. This is the immutable starting point for future versioned migrations;
there is no pre-v1 migration.
