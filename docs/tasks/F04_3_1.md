## Closed Findings

- Operation-index FaultPlan can return a typed `StorageFailure`.
- Operation logs distinguish `COMPLETED` from `RETURNED_FAILURE`.
- Partial-media-access, storage-full, and cleanup-denial integration scenarios
  use deterministic operation-index faults.
- Cleanup denial observes the Fake source entry and bytes before and after the
  denied authorization, and records no successful cleanup authorization.
- In-memory Journal operations support `PLANNED`, `EXECUTING`, and `COMPLETED`.
- Planned steps support `PLANNED`, `EXECUTING`, and `COMPLETED`.
- Steps cannot skip indexes, complete twice, or run after operation completion.
- Operation completion requires every planned step to be completed.
- Watermark reflects only the contiguous completed-step prefix.
- A process-killed step remains `EXECUTING` and does not advance watermark.
- Recovery integration covers both `NONE` and `PARTIAL_IMPORT` Manifest state.
- SourceDecision integration uses one test-only key builder for the frozen
  `kind:root:path:size:mtimeNormalized` format.
