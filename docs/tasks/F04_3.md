四、最小集成场景

A. SourceDecision fingerprint invalidation

Given:
- SourceDecision 的 sourceKey 由 kind/root/path/size/mtimeNormalized 生成；
- 当前源 fingerprint 与决策保存时一致。

Then:
- 决策可命中。

When:
- size 或 mtimeNormalized 任一改变。

Then:
- 旧 SourceDecision 不再命中；
- 不得删除或覆盖旧记录；
- 新 fingerprint 可形成独立 sourceKey。

B. ImportRecord source/copy linkage

Given:
- Room 中存在 COMMITTED ImportRecord(sourceFileId, targetFileId)。

Then:
- sourceFileId 与 targetFileId 都标记为 imported linkage；
- 两者都不进入普通重复候选；
- 无关联的第三个 fileId 仍可进入普通重复候选；
- 不得把 source 与 target 错折叠为同一个 FileFact。

C. Partial media access mapping

Given:
- FakeSourceReader 在 SOURCE_ENUMERATION 或 SOURCE_READ 返回 AccessDenied。

Then:
- DomainFailure.resolve() 为 PARTIAL_MEDIA_ACCESS；
- 不得映射为 WRITE_PERMISSION_LOST；
- 已枚举/已选择的可见项状态不被伪造为全量扫描。

D. Storage full mapping

Given:
- test-only Fake/FaultPlan 在 workspace write 返回 InsufficientSpace。

Then:
- 映射为 STORAGE_FULL；
- 不产生 final；
- 不产生 Manifest COMMITTED；
- 不写入 committed ImportRecord。

E. Target conflict mapping

Given:
- finalTarget 已被 part/final/trash 任一状态占用。

Then:
- Workspace 返回 Conflict；
- 映射为 TARGET_CONFLICT；
- source part 与既有 target 均保持不变；
- 不产生 committed metadata。

F. Cleanup denial preserves archive metadata

Given:
- archive metadata 已通过 Room transaction 提交；
- FakePermanentDeleter 对 SOURCE_CLEANUP_AUTH 返回 AccessDenied。

Then:
- 映射为 SOURCE_DELETE_AUTH_DENIED；
- ImageAsset、target FileFact、AssetFile、AlbumMembership、ImportRecord 均保留；
- source 保留；
- 不回滚已提交归档 metadata；
- 不记录 source 已删除的假状态。

G. Interrupted copy

Given:
- FaultPlan 在 writePart 中触发 PARTIAL_WRITE 或 SIMULATED_PROCESS_KILL。

Then:
- partial bytes 可检查；
- final 不存在；
- Manifest 不得为 COMMITTED；
- Room 不得存在 committed ImportRecord；
- 后续操作不得伪造完成。

H. Pre-Manifest interruption

Given:
- part/final 或 Room Journal metadata 已产生；
- Manifest writeImporting 尚未成功。

Then:
- 可从纯内存状态构造 recovery input/snapshot；
- Manifest state 为 NONE 或 PARTIAL_IMPORT，不得为 COMMITTED；
- 恢复输入包含 operationId、step/watermark 与可检查 workspace 状态；
- 不创建任何磁盘 Journal 或 Manifest 文件。

I. In-memory Journal semantics

使用 test-only in-memory Journal harness 验证：

- operation 与 step 状态按合法顺序推进；
- watermark 单调递增；
- 同一 operationId/stepIndex 不重复；
- process-kill 后保留最后已完成 step；
- 未执行 step 不得标记完成；
- 全程不创建 disk Journal 文件。

该 harness 只用于测试，不得定义或暗示 J1 的生产 disk Journal 实现。

五、必需断言

[ ] 所有故障由固定 operation index 触发，不使用 sleep/random。
